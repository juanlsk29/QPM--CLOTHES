# QPM Clothes — Historias de usuario

## 1. Propósito

Este documento resume el Product Backlog de QPM Clothes. Las historias
describen las funcionalidades que necesita el usuario para gestionar
y hacer seguimiento de los pedidos de una tienda de ropa.

El documento Word independiente de Historias de Usuario contiene el
detalle de cada historia, sus requisitos y sus criterios de aceptación.

## 3. Descripción resumida de las historias

### HU-001. Registrar un pedido

Como encargado de la tienda, quiero registrar un pedido para guardar
la información básica de una solicitud de ropa.

### HU-002. Registrar las prendas solicitadas

Como encargado de la tienda, quiero agregar las prendas, tallas,
colores y cantidades para conocer lo solicitado en cada pedido.

### HU-003. Consultar el listado de pedidos

Como encargado de la tienda, quiero consultar todos los pedidos
registrados para revisar su estado general.

### HU-004. Consultar el detalle de un pedido

Como encargado de la tienda, quiero consultar un pedido específico
para conocer sus datos y las prendas solicitadas.

### HU-005. Actualizar datos permitidos de un pedido

Como encargado de la tienda, quiero corregir los datos que puedan
modificarse para mantener la información actualizada.

### HU-006. Actualizar el estado de un pedido

Como encargado de la tienda, quiero cambiar el estado de un pedido
para realizar seguimiento de su preparación y entrega.

### HU-007. Cancelar un pedido

Como encargado de la tienda, quiero cancelar un pedido permitido
para indicar que ya no debe continuar su proceso habitual.

### HU-008. Identificar pedidos próximos a vencer y atrasados

Como encargado de la tienda, quiero identificar los pedidos cercanos
a su fecha de entrega o que ya estén atrasados para priorizar su atención.

### HU-009. Buscar y filtrar pedidos

Como encargado de la tienda, quiero buscar y filtrar pedidos para
encontrar información sin revisar manualmente todo el listado.

### HU-010. Consultar el historial de estados

Como encargado de la tienda, quiero consultar los cambios de estado
de un pedido para conocer su evolución.

### HU-011. Guardar y recuperar pedidos mediante JSON

Como usuario, quiero que los pedidos se guarden y recuperen mediante
archivos JSON para conservar la información entre ejecuciones.

### HU-012. Validar datos y controlar errores

Como usuario, quiero recibir mensajes claros cuando ingrese datos
incorrectos para poder corregirlos sin cerrar inesperadamente el programa.

### HU-013. Exportar reportes de pedidos en CSV

Como encargado de la tienda, quiero exportar información de pedidos
a CSV para consultarla en una hoja de cálculo.

### HU-014. Navegar mediante el menú de consola

Como usuario, quiero utilizar un menú claro para acceder a las
funcionalidades sin tener que conocer el código.

### HU-015. Consultar un resumen de pedidos

Como encargado de la tienda, quiero consultar un resumen general
para revisar la cantidad de pedidos según su estado y situación.



## 4. Criterio de priorización

La prioridad principal es contar con una aplicación que permita
registrar, guardar, consultar y actualizar pedidos correctamente.

Las funciones complementarias no deben retrasar las pruebas,
la documentación ni la entrega de las funciones esenciales.
